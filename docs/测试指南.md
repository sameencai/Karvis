# Karvis 测试指南

> 最后更新：2026-02-11

---

## 一、系统架构速览

```
用户(企业微信) ──POST──▶ /wework(消息网关)
                           │ 解密 + 去重 + 异步
                           ▼
                      /process(消息处理)
                           │
                           ▼
                      brain.py(LLM决策)
                       ├─ 选择 skill
                       ├─ 生成 reply
                       └─ state/memory 更新
                           │
                           ▼
                      skills/(技能执行)
                           │
                           ▼
                      OneDrive(持久化)

定时器(Karvis-scheduler) ──POST──▶ /system(系统端点)
```

### 端点一览

| 端点 | 方法 | URL | 用途 |
|------|------|-----|------|
| `/` | GET | `https://your-scf-url.tencentscf.com/` | 健康检查 |
| `/wework` | GET/POST | `https://your-scf-url.tencentscf.com/wework` | 企微消息入口 |
| `/process` | POST | `https://your-scf-url.tencentscf.com/process` | 内部消息处理 |
| `/system` | POST | `https://your-scf-url.tencentscf.com/system` | 定时任务/手动触发 |

---

## 二、前置条件

- 腾讯云 SCF 控制台权限
- curl 或 Postman（用于手动触发 /system）
- 企业微信测试账号（用户 ID: `YourUserID`）
- OneDrive 网页版（查看文件写入结果，比 Obsidian 同步更快）
- SCF 日志查看权限（排查问题用）

## 三、三种测试方式

### 方式 A：curl 调用 /system（适用于所有系统动作）

```bash
# 模板
curl -X POST \
  https://your-scf-url.tencentscf.com/system \
  -H "Content-Type: application/json" \
  -d '{"action":"动作名称"}'
```

### 方式 B：SCF 控制台测试（适用于 Karvis-scheduler 函数）

1. 打开 [腾讯云 SCF 控制台](https://console.cloud.tencent.com/scf/list)
2. 找到 **Karvis-scheduler** Event 函数
3. 在「测试」标签，填入测试事件：
```json
{
  "Message": "{\"action\":\"morning_report\"}"
}
```
4. 点击「测试」→ 查看执行结果和日志

### 方式 C：企业微信直接发消息（适用于所有用户交互功能）

在企微给 Karvis 发消息，观察：
1. **企微回复内容**（即时反馈）
2. **OneDrive 文件变化**（打开 [OneDrive 网页版](https://onedrive.live.com) 查看）
3. **SCF 日志**（调试用：SCF 控制台 → 函数管理 → 日志查询）

**验证点**：确认 SCF 函数运行正常、Flask 路由正常。

#### 1.2 refresh_cache — 缓存刷新

**作用**：清除 prompt 文件（SOUL/SKILLS/RULES/MEMORY）和 state 的内存+磁盘缓存，下次请求会重新从 OneDrive 读取最新内容。

**触发**：
```bash
curl -X POST \
  https://your-scf-url.tencentscf.com/system \
  -H "Content-Type: application/json" \
  -d '{"action":"refresh_cache"}'
```

**预期返回**：`{"ok": true, "action": "refresh_cache"}`

**什么时候需要用**：
- 修改了 `prompts/RULES.md`、`SKILLS.md`、`SOUL.md`
- 修改了 `memory/memory.md`
- 不想等 30 分钟缓存自动过期

#### 1.3 morning_report — 晨报（含 F3 时间胶囊 + F13 天气）

**定时触发**：每天 08:00  
**手动触发**：
```bash
curl -X POST \
  https://your-scf-url.tencentscf.com/system \
  -H "Content-Type: application/json" \
  -d '{"action":"morning_report"}'
```

**处理流程**：
1. 读取 `Todo.md`（今日待办）
2. 读取 `Quick-Notes.md`（最近消息）
3. 构建**时间胶囊**：读取 7天前 / 30天前 / 365天前 的 Quick-Notes 和 Daily Note
4. 获取**天气信息**（V3-F13）：调用心知天气 API 获取城市当日天气
5. 所有数据注入 context → 交给 LLM 生成晨报

**预期返回**：`{"ok": true, "action": "morning_report", "has_reply": true}`

**验证点**：
| 检查项 | 方式 | 期望 |
|--------|------|------|
| 企微收到晨报 | 查看企微 | 包含待办提醒、天气问候等 |
| 天气信息自然融入 | 查看企微 | 不是"播报"式，而是自然嵌入问候（如"今天城市多云，23~28°C~"） |
| 时间胶囊出现 | 查看企微 | 如果历史数据存在，末尾有「📅 时间胶囊」段 |
| 无历史数据时 | 查看企微 | 不出现时间胶囊段（正常） |
| Top 3 引导 | 查看企微 | 末尾有"今天最重要的 3 件事是什么？"类似引导 |
| SCF 日志 | SCF 控制台 | `[Weather] 城市: xxx xx~xx°C` 日志 |

**测试 F3 时间胶囊的前提**：
- Quick-Notes.md 中需要有 7 天前（或 30/365 天前）的条目
- 条目格式必须是 `### HH:MM` 并且在对应日期下

**测试 F13 天气的前提**：
- `config.py` 中 `WEATHER_API_KEY` 已配置（默认已硬编码）
- 心知天气 API 可访问

#### 1.5 todo_remind — 待办提醒

**定时触发**：每天 09:00 / 14:00 / 18:00（3 次）  
**手动触发**：
```bash
curl -X POST \
  https://your-scf-url.tencentscf.com/system \
  -H "Content-Type: application/json" \
  -d '{"action":"todo_remind"}'
```

**处理流程**（不走 LLM，纯逻辑）：
1. 读取 `state.reminders` 数组
2. 检查每个 reminder 的 `remind_at`（提前30分钟预警 + 到时正式提醒）
3. 检查 `due_date`（当天提醒 + 过期警告）
4. 自动清理 7 天前已通知的过期提醒

**预期返回**：`{"ok": true, "action": "todo_remind", "sent": N}`（N 为发送的提醒数）

**测试前准备**：
1. 在企微发消息：`帮我添加一个待办：明天下午三点开会，提醒我`
2. 确认 `state.reminders` 中已注册（OneDrive 查看 `.ai-life-state.json`）
3. 调整 `remind_at` 为当前时间附近（如果想立即触发的话）
4. 再调用 `todo_remind`

**验证点**：
| 检查项 | 方式 | 期望 |
|--------|------|------|
| 到期提醒推送 | 查看企微 | 收到待办提醒消息 |
| 未到期无提醒 | 查看返回值 | `"sent": 0` |
| state 更新 | OneDrive `.ai-life-state.json` | reminder 的 notified 字段更新 |

#### 1.9 nudge_check — 轻推检测（F5）

**定时触发**：每天 14:00  
**手动触发**：
```bash
curl -X POST \
  https://your-scf-url.tencentscf.com/system \
  -H "Content-Type: application/json" \
  -d '{"action":"nudge_check"}'
```

**处理流程**（纯规则引擎，不走 LLM）：
1. 读取 `state.nudge_state`（上次消息日期、streak、mood_scores）
2. 按规则判断是否需要推送：

| # | 场景 | 检测条件 | 推送消息 |
|---|------|----------|----------|
| 1 | 沉默检测 | 今天 14:00 前无消息 | "小明今天很安静呀，是忙还是累了？" |
| 2 | 情绪跟进 | 昨天 mood_score ≤ 4 | "昨天好像有点低落，今天好点了吗？" |
| 3 | 连续记录鼓励 | streak 达到 3/7/14/21... | "你已经连续记录 N 天了！" |

3. 符合条件的消息直接推送企微

**预期返回**：`{"ok": true, "action": "nudge_check", "sent": N}`

**验证点**：
| 检查项 | 方式 | 期望 |
|--------|------|------|
| 沉默检测 | 当天未发消息时 14:00 触发 | 收到问候消息 |
| 情绪跟进 | 手动设置 state.mood_scores 昨天 ≤ 4 后触发 | 收到情绪跟进消息 |
| 无需推送 | 当天已发消息 + 昨天心情好 | `{"sent": 0}` |

**注意**：morning_report 和 evening_checkin 也会注入 nudge 上下文（`context.nudge`），包含：
- `yesterday_mood`：昨天情绪
- `streak`：连续记录天数
- `last_message_hours_ago`：距上次消息小时数
- `people_to_follow_up`：超过 7 天未提及的重要人物
- `checkin_streak`：打卡连续天数

### ▌Part 2：用户消息触发的技能（通过企微发消息，共 33 个 skill）

#### 2.1 note.save — 笔记保存（自动）

**说明**：这个 skill 不需要手动触发。**所有用户消息都会自动保存到 Quick-Notes.md**（打卡消息除外），这是 brain.py 的统一行为。

**测试方法**：在企微随便发一条消息，比如 `今天天气真好`

**验证点**：
| 检查项 | 方式 | 期望 |
|--------|------|------|
| Quick-Notes 追加 | OneDrive `00-Inbox/Quick-Notes.md` | 出现 `### HH:MM` + 消息内容 |
| 日期分组 | Quick-Notes.md | 按 `## YYYY-MM-DD` 分组 |
| 企微回复 | 查看企微 | 有适当的回复（不是纯确认） |

#### 2.2 classify.archive — 分类归档

**说明**：LLM 判断消息适合归档时自动触发（通常在保存到 Quick-Notes 的同时）。

**测试方法**：发一条明确有分类倾向的消息：
- 工作类：`今天写了个新接口，处理并发的逻辑挺复杂的`
- 情感类：`今天特别开心，终于把困扰很久的事情解决了`

## 九、常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 修改了 RULES/SKILLS/SOUL.md 没生效 | 30 分钟缓存未过期 | `curl refresh_cache` |
| 修改了 memory.md 没生效 | 同上 | `curl refresh_cache` |
| morning_report 没有时间胶囊 | 7/30/365 天前没有数据 | 正常现象，有历史数据才会出现 |
| mood_generate 返回「没有记录」 | 当天没有任何消息/笔记 | 先发几条消息再测 |
| 打卡后 mood_scores 没更新 | state 缓存未过期(5min TTL) | 等 5 分钟或 `refresh_cache` |
| OneDrive 文件没变化 | 同步延迟 | 等 1-2 分钟，或用 OneDrive 网页版直接查看 |
| SCF 超时 | 默认 120 秒不够（如 book.summary 二次 LLM） | SCF 控制台调大超时时间 |
| 部署新代码但旧逻辑还在 | SCF 热实例缓存 | 等几分钟冷启动，或强制重新部署 |
| 语音消息没识别 | ASR 服务异常 | 检查 SCF 日志，确认腾讯云 ASR 配置 |
| 企微消息发了没回复 | 异步调用 /process 失败 | 检查 SCF 日志，确认 API Gateway URL 正确 |
| 企微回复「AI 暂时不可用」 | DeepSeek API 异常 | 检查 API Key 和余额，查看 SCF 日志 |
| 消息被吞（收到消息但没处理） | 60 秒内消息去重 | 正常机制，避免重复处理 |
| 打卡问到一半中断了 | 12 小时超时 | 下次发消息会自动完成未完成打卡 |
| book.summary/quotes 很慢 | 二次 LLM 调用 | 正常，耐心等待（建议 SCF 超时 ≥ 180s） |
