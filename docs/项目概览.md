# Karvis — 项目概览

## 项目信息

| 字段 | 值 |
|------|-----|
| 名称 | Karvis |
| 一句话介绍 | 运行在企微上的个人 AI 助手，多模型调度（DeepSeek V3.2 + Qwen Flash），数据存 Obsidian (OneDrive) 或本地 (Lite 模式) |
| 部署平台 | 腾讯云 SCF (生产) / 本地 + Docker (Lite 模式) |
| 运行环境 | Python 3.9+, Flask |
| LLM | 三层模型架构：Flash(Qwen Flash/阿里云) + Main(DeepSeek V3.2 thinking=off) + Think(DeepSeek V3.2 thinking=on) |

### 产品能力一句话总结

| 层级 | 核心价值 | 能力数 |
|------|---------|--------|
| 信息收集 | 零摩擦输入——发条消息就是记录 | 5 种输入类型 + 自动 ASR + 链接解析 |
| 智能理解 | 不只是转发——真正理解你在说什么 | 35 种 Skill 路由 + 多步推理 + 情境感知 |
| 日常记录 | 碎片不丢失——自动归档到对的地方 | 笔记/读书/影视/语音日记，4 类 8 个归档目录 |
| 效率工具 | 不止记住——帮你推进和复盘 | 待办/Top3/习惯实验/决策复盘 |
| 陪伴互动 | 有事才发——主动但不打扰 | 闲聊/主动陪伴/轻推/人际追踪 |
| 洞察生成 | 数据变洞察——定期+按需双模式 | 6 种定期报告 + 主题深潜 + 笔记查阅 |
| 数据沉淀 | 你的数据你拥有——全存 Obsidian | 手机+电脑同步，随时可查可编辑 |

### 多模型路由策略

| 场景 | 模型层级 | 模型 | 原因 |
|------|---------|------|------|
| 用户日常消息 | Main | DeepSeek V3.2 thinking=off | 分类+回复不需要深度推理，速度优先 |
| 系统报告（晨报/日报等） | Main | DeepSeek V3.2 thinking=off | 生成类任务 |
| 主动陪伴 companion_check | Flash | Qwen Flash | 轻量任务，1-3s 极速响应 |
| 深度分析（deep_dive / decision_track）| Think | DeepSeek V3.2 thinking=on | 需要思维链 |
| 语音日记 voice_journal | Main | DeepSeek V3.2 thinking=off | 结构化整理 |
| Agent Loop 内部 | Main | DeepSeek V3.2 thinking=off | 多轮工具调用 |

### 链接内容解析流程

```
用户发送消息
    ├── link 类型（企微分享卡片）
    │   └── _fetch_link_content(url) → BeautifulSoup 解析
    │       ├── 微信文章: div.rich_media_content
    │       ├── 通用网页: <article> → <body>
    │       └── 失败: 降级到只传 title/url
    │
    └── text 类型（纯 URL 文本）
        └── _extract_url(text) → 检测是否为纯 URL
            ├── 是: _fetch_link_content() → 同上
            └── 否: 正常文本处理
```

### 主动陪伴流程

```
Scheduler 每2小时触发 companion_check (8:00-22:00)
    │
    ▼ 五层防骚扰检测
    ├── ① 安静时间 0-7 → cron不触发 + 代码双保险
    ├── ② 近期互动 <2h → 跳过
    ├── ③ 推送间隔 <4h → 跳过
    ├── ④ 每日上限 ≥3次 → 跳过
    └── ⑤ 无信号 → 静默跳过
    │
    ▼ 信号收集
    ├── 沉默 >4h
    ├── 待办未完成
    └── 昨日情绪低落(≤4)且未跟进
    │
    ▼ 上下文收集 (ThreadPoolExecutor并发)
    ├── SOUL.md + Memory.md
    ├── Quick-Notes (最近20行)
    ├── Todo.md
    └── recent_messages (最近5条)
    │
    ▼ Flash LLM 生成关怀消息 (1-2句, 温度0.7)
    │
    ▼ 推送企微 + 更新 nudge_state 计数器
```

## 数据流向

### 消息存储逻辑

```
用户发送消息
    ↓
统一写入 Quick-Notes（所有消息的原始流水记录）
    ↓
LLM 判断是否需要额外归档
    ├── classify.archive → 工作/情感/趣事/碎碎念 对应目录
    ├── todo.add/done/list → Todo.md
    ├── book.*/media.* → 读书/影视笔记
    └── ignore → 只留在 Quick-Notes，不额外归档
```

## 性能关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `PROMPT_CACHE_TTL` | 1800s (30分) | 三级缓存：内存 → /tmp 磁盘 → OneDrive |
| `STATE_CACHE_TTL` | 300s (5分) | State 本地缓存，内存 → /tmp → OneDrive |
| `RECENT_MESSAGES_LIMIT` | 10 条 | 短期记忆滑动窗口，超限触发对话压缩 |
| OneDrive 读超时 | `(5, 10)` | connect 5s + read 10s，超时立即重试 |
| OneDrive 写超时 | `(5, 15)` | connect 5s + read 15s |
| 最大重试 | 3 次 | 无 sleep，立即重试 |
| 线程池 | 6 workers | 并发 OneDrive 读写 |
| Session 连接池 | 6 connections | TCP+TLS 复用 |
| LLM max_tokens | 500 | 路由决策不需要长输出 |
| SCF 超时 | 900s | Web 函数执行超时（建议 ≥300s） |
| SCF 内存 | 512 MB | |

## 常见任务入口

| 任务 | 看哪里 |
|------|--------|
| 排查消息处理慢 | `brain.py` 中的 `[Brain][耗时]` 日志 |
