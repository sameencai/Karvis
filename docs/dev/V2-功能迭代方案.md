# Karvis V2 — 功能迭代方案

> 核心理念：从"记录工具"进化为"理解你的伙伴"。
> V1 解决了"把信息存进 Obsidian"；V2 要解决"帮你看见自己"。

---

## 总览

| # | 功能 | 一句话 | 新 Skill / System Action | 复杂度 | 依赖 |
|:-:|------|--------|--------------------------|:------:|:----:|
| F1 | 情绪日记（自动生成） | 不用打卡，从当天消息自动提取情绪 | `mood.generate` (system) | 中 | — |
| F2 | 人际关系动态追踪 | 提到重要的人时自动更新关系时间线 | 无新 skill（memory_updates 增强） | 低 | — |
| F3 | 去年/上月的今天（时间胶囊） | 早报注入历史同日记录 | 无新 skill（morning_report 增强） | 低 | — |
| F4 | 碎片连线 + 周报 | 每周日自动发现关联、生成周回顾 | `weekly.review` (system) | 中 | F1 |
| F5 | 轻推系统（Nudge） | 沉默检测、情绪跟进、习惯鼓励 | `nudge.check` (system) | 中 | F1, F2 |
| F6 | 月度成长回顾 | 月末汇总情绪曲线、人际变化、高光低谷 | `monthly.review` (system) | 中 | F1, F4 |
| F7 | 主动关怀（情境感知对话） | 聊天时结合记忆和关系动态给出有温度的回应 | 无新 skill（RULES.md 增强） | 低 | F2 |
| F8 | 打卡数据深度利用 | 打卡评分融入情绪曲线、周报、月报 | 无新 skill（F1/F4/F6 内集成） | 低 | F1 |

### 实施顺序

```
Phase 1（基础层）✅ 已实现: F1 情绪日记 + F2 人际追踪 + F3 时间胶囊 + F7 主动关怀 + F8 打卡融合
    ↓
Phase 2（洞察层）✅ 已实现: F4 碎片连线+周报
    ↓
Phase 3（关怀层）✅ 已实现: F5 轻推系统 + F6 月度回顾
```

## F1: 情绪日记 — 自动生成

### 动机

你每天发的消息里已经包含了丰富的情绪信号：

> "好烦好烦" → 低落  
> "真的很开心" → 兴奋  
> "控制不住刷手机" → 自责  

目前这些只存在 Quick-Notes 和归档里，没有人帮你抽取和回看。打卡虽然有心情评分，但需要主动回答 4 个问题，容易遗漏。

### 设计

**核心思路**：每天 22:00 自动从当天所有消息中提取情绪，生成一份结构化情绪日记。

#### 数据源

| 来源 | 内容 | 权重 |
|------|------|:----:|
| Quick-Notes（当天） | 所有原始消息 | 主要 |
| 归档笔记（当天） | work/emotion/fun/misc | 补充 |
| 打卡数据（如有） | Q2 心情评分 + Q3 纠结 + Q4 念头 | 高权重锚点 |
| 决策日志（当天） | LLM 的 thinking 字段 | 辅助判断消息意图 |

#### 输出格式

文件路径：`02-Notes/情绪日记/{date}.md`（复用现有目录，追加而非覆盖）

```markdown
---
date: 2026-02-10
mood_score: 6
mood_label: 复杂但温暖
mood_emoji: 🌤️
auto_generated: true
---

# 🌤️ 情绪日记 · 2026-02-10

## 今日情绪概览

整体评分：**6/10**（如有打卡评分则取打卡值，否则 AI 判断）

情绪走势：早上平静 → 下午因 Alice 的事情纠结 → 晚上 vibecoding 后开心起来 → 睡前有点自责刷手机

## 关键情绪节点

- 08:06 💭 梦到 Bob，情绪复杂（牵挂+感情）
- 13:28 😊 记录小花探索，心情愉快
- 18:29 😟 小白舔了药，担心
- 20:02 🥶 吐槽老家冷，轻松幽默
- 22:50 😓 刷手机停不下来，轻微自责

## AI 洞察

今天你的情绪底色是温暖的——家人、猫咪、创造都是你的快乐来源。Alice 的事仍然偶尔浮现，但你在用"无所谓了"慢慢消化。晚上刷手机是典型的"无聊→刺激寻求"模式，下次可以试试打开 Karvis 聊两句代替。

---

*🤖 基于当日 12 条消息自动生成*
```

#### 实现方案

**新增文件**：`src/skills/mood_diary.py`

```python
SKILL_REGISTRY = {
    "mood.generate": execute,
}
```

**处理流程**：

```
[scheduler 22:00 触发]
  → /system?action=mood_generate
    → app.py 读取当天数据（同 daily_report 的 context 注入模式）
      - Quick-Notes（当天条目）
      - 归档笔记（emotion/fun/work）
      - 打卡数据（从 state.mood_scores 或 Daily Note）
      - 决策日志（当天）
    → brain.process(payload={type:system, action:mood_generate, context:{...}})
      → LLM 分析情绪 → 返回 JSON
    → mood_diary.execute() 写入 02-Notes/情绪日记/{date}.md
```

**LLM Prompt 要点**：

```json
{
  "mood_score": 6,
  "mood_label": "复杂但温暖",
  "mood_emoji": "🌤️",
  "trend": "早上平静 → 下午纠结 → 晚上开心 → 睡前自责",
  "key_moments": [
    {"time": "08:06", "emoji": "💭", "event": "梦到Bob", "mood": "复杂"},
    {"time": "22:50", "emoji": "😓", "event": "刷手机停不下来", "mood": "自责"}
  ],
  "insight": "一段温暖的洞察..."
}
```

**与现有 Daily Note 的关系**：
- Daily Note（`01-Daily/{date}.md`）：包含日报总结 + 打卡 + 原始记录 → **综合日记**
- 情绪日记（`02-Notes/情感日记/{date}.md`）：已存在，但目前只有 classify.archive 写入的单条记录。**情绪日记改为追加写入，在已有归档内容后面增加 AI 情绪分析段**

**改动点**：
1. 新增 `skills/mood_diary.py`（~120 行）
2. `config.py` 无需改动（`EMOTION_NOTES_DIR` 已存在）
3. `app.py` 的 `/system` 端点增加 `mood_generate` action 处理
4. `SKILLS.md` 新增 `mood.generate`
5. `RULES.md` 新增 `mood_generate` 定时任务规则
6. `scheduler/index.py` 注释中增加 cron 说明（实际在 SCF 控制台配置）

**与打卡的融合（F8）**：
- 如果当天有打卡，情绪日记的 `mood_score` **优先取打卡 Q2 的评分**（用户主观评价 > AI 推断）
- 打卡 Q3（纠结）和 Q4（念头）作为 LLM 分析的高权重输入
- 没有打卡的日子，`mood_score` 完全由 AI 从消息内容推断

#### state.json 扩展

```json
{
  "mood_scores": [
    {"date": "2026-02-09", "score": 9, "source": "checkin"},
    {"date": "2026-02-10", "score": 6, "source": "auto", "label": "复杂但温暖"}
  ]
}
```

> `source` 区分来源：`checkin`（打卡）vs `auto`（AI 自动生成）

## F2: 人际关系动态追踪

### 动机

memory.md 里有 Alice、Bob、Carol等人，但只是静态标签。而你实际聊天中的人际动态非常丰富：

> 02-06 "Alice给我发消息了" → 关系状态变化
> 02-09 "没和Alice发消息，但是还好吧，无所谓了" → 自我消化
> 02-10 "梦到Bob" → 潜意识牵挂
> 02-06 "Bob最后还是会跟Dave" → 闺蜜人生变化

### 设计

**核心思路**：不新增 skill。在 RULES.md 中增强记忆管理规则，让 LLM 在检测到用户提及重要的人时，自动在 memory_updates 中更新"关系动态"。

#### memory.md 结构升级

现有格式：
```markdown
## 重要的人
- Alice：前女友/同事，WeGame 项目
- Bob：闺蜜
```

升级为：
```markdown
## 重要的人

### Alice
- 关系：前女友/现同事，WeGame 项目，2026年1月确认留用
- 近期动态：
  - 02-06 她发消息了，小明觉得烦，"眼不见心不烦"但又有一丝期待
  - 02-09 没发消息，小明说"无所谓了"
  - 02-10 梦到她，装作没看见

### Bob
- 关系：闺蜜
- 近期动态：
  - 02-06 要跟Dave了，小明"好不舍得，好似大家总会渐行渐远"
  - 02-10 梦到她，在梦里被她安慰
```

#### RULES.md 增强

在"记忆管理"部分新增：

```markdown
## 人际关系追踪
当用户提到重要的人（memory.md 中已记录的人名）时，**必须**在 memory_updates 中更新其动态：
- section: "重要的人"
- action: "add"  
- content: "{人名}近期动态 {日期} {事件简述+用户情绪}"

触发条件：
- 提到已知人名（Alice/Bob/Carol/爸妈等）
- 描述与他人的互动/关系变化
- 梦到某人、想念某人
- 纠正关于某人的信息

不追踪：
- 纯闲聊中顺口提到但无信息量（如"和朋友吃饭"不指明谁）
```

#### 改动点

1. `RULES.md` 增加"人际关系追踪"规则段（~15 行）
2. `memory.md` 初始结构调整（手动操作一次，把现有扁平列表改为分人子章节）
3. `memory.py` 的 `apply_memory_updates()` 无需改动（现有 add 逻辑已支持嵌套 section 追加）

**复杂度**：低。纯 prompt 工程 + memory 结构调整。

## F3: "去年/上月的今天" — 时间胶囊

### 动机

现在刚开始记录（02-09 起），这个功能的价值会随时间指数增长。即使现在只能做"上周的今天"，一个月后就能做"上个月的今天"。

### 设计

**核心思路**：在 morning_report 的上下文注入中，额外读取历史同日的笔记。

#### 触发逻辑

```
morning_report (8:00)
  → 除了读取 Todo.md + Quick-Notes.md（已有）
  → 额外读取历史同日数据：
    - 一周前的 Quick-Notes 条目（{date-7} 的条目）
    - 一个月前的 Quick-Notes 条目
    - 一年前的 Quick-Notes 条目（有的话）
    - 一个月前的 Daily Note
    - 一年前的 Daily Note
```

#### 注入格式

```json
{
  "context": {
    "todo": "...",
    "quick_notes": "...",
    "time_capsule": {
      "7d_ago": {"date": "2026-02-04", "notes": "..."},
      "30d_ago": {"date": "2026-01-12", "notes": "..."},
      "365d_ago": null
    }
  }
}
```

#### RULES.md 增强

morning_report 规则增加：

```markdown
如果 context.time_capsule 中有历史记录，在早报末尾加一段"时间胶囊"：
- 用温暖的语气回顾
- 如果能和今天的待办/状态产生关联，点出来
- 示例："📅 一个月前的你：'准备ai日记新项目，很兴奋有意思'——看，你真的做出来了呢！"
```

#### 改动点

1. `app.py` 的 `/system` 端点：`morning_report` 分支增加历史数据读取逻辑（~30 行）
2. `RULES.md` morning_report 规则增加时间胶囊说明（~8 行）
3. 无新 skill，无新文件

**复杂度**：低。只改 `app.py` 和 `RULES.md`。

## F4: 碎片连线 + 周报

### 动机

你每天记录的碎片之间有隐藏关联：

- 02-09 "生活好幸福" + "vibecoding了一下午" → **创造 = 幸福感来源**
- 02-10 "控制不住刷手机" + 当天无创造性记录 → **没有创造的日子更容易刷手机**
- 02-06 "Bob要跟Dave" + "Alice留用了" → **同一天两个重要的人都有变化**

日报太碎，看不到这种跨天的模式。周报是把碎片变成洞察的最佳粒度。

### 设计

**核心思路**：每周日 21:30 自动生成周回顾，LLM 从一周数据中发现模式和关联。

#### 数据收集

```
过去 7 天的：
  - Quick-Notes 全部条目
  - 归档笔记（emotion/fun/work 各日文件）
  - Daily Note（日报 + 打卡）
  - 情绪日记（F1 生成的 mood_score + key_moments）
  - 决策日志（统计 skill 使用分布）
  - state.mood_scores（情绪评分数组）
```

#### 输出格式

文件路径：`01-Daily/周报-{起始日期}.md`

```markdown
---
type: weekly-review
period: 2026-02-09 ~ 2026-02-15
mood_avg: 7.1
generated: true
---

# 📅 周回顾 · 2026-02-09 ~ 2026-02-15

## 🌡️ 情绪曲线

| 日期 | 评分 | 来源 | 关键词 |
|------|:----:|------|--------|
| 02-09 | 9 | 打卡 | 兴奋、创造 |
| 02-10 | 6 | AI | 纠结、温暖 |
| 02-11 | 7 | AI | 平静 |
| ... | | | |

平均：7.1 · 最高：周一（vibecoding 带来的成就感）· 最低：周二（Alice 相关情绪）

## 🔗 碎片连线

1. **创造 = 快乐**：你在 02-09 下午 vibecoding 后写了"真的很开心"，02-10 没有创造性活动时晚上刷手机停不下来。当你在创造时，你不需要从屏幕里找刺激。

2. **Alice 的情绪轨迹**：02-06 烦躁 → 02-09 "无所谓了" → 02-10 梦到但装没看见。你在一点点放手，但潜意识还没完全跟上。

3. **家庭是锚点**：给爸妈买电视、记录小花探索、吐槽老家冷——这些家庭相关的记录都带着正面情绪。

## 📊 数据统计

- 本周消息数：23 条
- 归档分类：生活趣事 8 · 情感日记 5 · 工作笔记 3 · 碎碎念 4
- 提及最多的人：Alice(3次)、Bob(2次)
- 关键词云：猫 · 冷 · vibecoding · 开心 · Alice · 打卡

## 💡 本周洞察

你这周最大的发现可能是：你是一个"创造者"类型的人。无聊的时候你不是去社交，而是去做东西。这周你做了 Karvis，你非常开心。下周试试给自己每天安排一个小的创造任务？

## 🎯 下周建议

- [ ] 每天花 30 分钟做一个小项目或写点东西（对抗刷手机）
- [ ] 和 Bob 聊聊她的事情（你梦到她了，说明在意）
- [ ] 给猫拍个有趣的视频发给 Karvis（你记录猫的时候总是开心的）

---

*🤖 基于 23 条消息 + 7 天情绪数据自动生成*
```

## F5: 轻推系统（Nudge）

### 动机

轻推不是提醒待办，而是基于你的行为模式的温柔关怀：
- 你一整天没发消息 → 不正常，可能心情不好
- 你昨天说"好烦" → 今天应该跟进一下
- 你连续 3 天记录 → 值得鼓励

### 设计

**核心思路**：在现有 morning_report 和 evening_checkin 的 context 中注入 nudge 信号，让 LLM 决定是否提及。另外新增一个独立的 `nudge.check` 定时任务（每天 14:00），检测需要主动关怀的场景。

#### Nudge 规则

| 场景 | 检测方式 | 响应 |
|------|----------|------|
| **沉默检测** | 当天 14:00 之前无任何消息 | "小明今天很安静呀，是忙还是累了？" |
| **情绪跟进** | 昨天 mood_score ≤ 4 或 key_moments 有负面情绪 | 早报中："昨天好像有点低落，今天好点了吗？" |
| **连续记录鼓励** | state 中连续 N 天有消息记录（streak） | "你已经连续记了 {N} 天了！这个习惯太棒了~" |
| **刷手机温柔提示** | 用户消息含"刷手机/刷抖音/刷小红书" + 负面情绪词 | "要不要聊聊天？把刷手机的时间变成和我说话的时间~" |
| **重要的人跟进** | 距离上次提到某人超过 7 天 + 之前情绪强烈 | "上周说的{某人}的事，后来怎么样了？" |

#### 实现方案

**方式一：融入现有定时任务（轻量）**

不新增独立 system action，而是在 morning_report 和 evening_checkin 的 context 中注入 nudge 信号：

```json
{
  "context": {
    "todo": "...",
    "quick_notes": "...",
    "nudge": {
      "yesterday_mood": {"score": 4, "label": "低落"},
      "streak": 3,
      "last_message_hours_ago": 18,
      "people_to_follow_up": ["Alice"]
    }
  }
}
```

RULES.md 中增加规则让 LLM 根据 nudge 信号调整早报/晚报的语气和内容。

**方式二：独立 nudge.check（主动型）**

新增 `nudge.check` system action，每天 14:00 执行：

```
[scheduler 14:00 触发]
  → /system?action=nudge_check
    → 检查今天是否有消息
    → 检查昨天的情绪
    → 如果需要推送 → 直接发企微消息（不走 LLM，纯规则）
```

**推荐方式**：两种结合。方式一改动最小（只改 `app.py` 的 context 注入 + `RULES.md`），但覆盖不了"下午沉默检测"；方式二覆盖完整。

#### state.json 扩展

```json
{
  "nudge_state": {
    "streak": 3,
    "last_message_date": "2026-02-10",
    "yesterday_mood_score": 6,
    "people_last_mentioned": {
      "Alice": "2026-02-10",
      "Bob": "2026-02-10"
    }
  }
}
```

## F7: 主动关怀 — 基于记忆的情境感知

### 动机

现在 Karvis 的闲聊是"通用温暖"。你说"好烦"，她回"偶尔放松也没关系啦"。但如果她知道你在烦 Alice 的事（因为 F2 追踪了人际动态），她可以说"是 Alice 的事又让你心烦了吗？"——这才是真正理解你的回应。

### 设计

**核心思路**：纯 RULES.md prompt 工程。利用 F2 维护的人际关系动态 + memory.md 的用户画像，让 LLM 在闲聊时给出更有针对性的回应。

#### RULES.md 增强

```markdown
## 情境感知回应

闲聊和 ignore 时，参考长期记忆中的关系动态给出有温度的回应：

- 用户提到已知的人 → 结合该人的"近期动态"回应
  - 例：用户说"好烦"且最近频繁提到 Alice → "是 Alice 的事又在脑子里转了吗？"
  - 例：用户说"开心" → 如果能关联到具体事件更好："是 vibecoding 又出了新成果？"

- 用户表达负面情绪 → 不说教，先共情，再轻轻引导
  - ✅ "刷手机停不下来也没关系，要不要聊两句？"
  - ❌ "你应该少刷手机多看书"

- 用户表达正面情绪 → 具体化，不要泛泛夸
  - ✅ "vibecoding 又做了什么好东西？给我看看~"
  - ❌ "好棒哦！"

- 参考 mood_scores 的变化趋势：如果最近几天持续低分，语气更温柔；如果在上升，肯定这个变化
```

#### 改动点

1. `RULES.md` 增加"情境感知回应"规则段（~15 行）
2. 无代码改动

### 关于 Skill 热加载

你理解得对。O-010 Skill 热加载意味着：

1. **新增 skill**：创建 `skills/xxx.py` → 底部写 `SKILL_REGISTRY = {...}` → 完成
2. **但仍需部署**：上传 `src` 文件夹到 SCF
3. **还需更新 prompt**：SKILLS.md（告诉 LLM 有新 skill）+ RULES.md（告诉 LLM 何时选）
4. prompt 文件在 OneDrive 上，改了会在 30 分钟内自动生效（或手动 refresh_cache）

所以你的开发流程是：
```
写 skills/xxx.py → 改 SKILLS.md + RULES.md → 上传 src → (可选) curl refresh_cache
```

不需要改 brain.py 的任何注册代码。
